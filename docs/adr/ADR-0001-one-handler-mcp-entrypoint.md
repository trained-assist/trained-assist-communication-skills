# ADR-0001: Один handler, несколько дверей; своя лестница моделей запрещена

Status: Accepted · 2026-10-02 · Обновлён 2026-10-03 (рантайм Worker) · Эпик: trained-assist/trained-assist-communication-skills#1

## Контекст

Сервис должен обслуживать два типа потребителей: MCP-хост (через `generate_next_message_to_conversation_partner`) и доменные адаптеры (сейчас рекрутинг; далее sales и другие домены). Уже есть ревью контракта (trained-assist/trained-agent-architecture#125): один метод, общий retry budget, `model_profile` только по allowlist, PII-телеметрия.

## Решение

1. **Один handler** — вся логика генерации и guard'а живёт в одном месте (`src/handler.mjs`). Guard, которым закрывается генерация (общий retry budget), — тот же код, что и отдельная проверка готового сообщения: два входа в одну проверку, а не две реализации.
2. **Дверей несколько, логика одна.** `src/mcp/protocol.mjs` — чистая функция «JSON-RPC сообщение → ответ», без какого-либо I/O. Её драйвят:
   - `src/index.mjs` — Cloudflare Worker: `POST /mcp` (streamable HTTP) и `POST /v1/dialogs/next-message` (REST-лицо того же handler'а);
   - `src/mcp/entrypoint.mjs` — stdio-дверь для локальной песочницы и `node --test`.
   Логика, добавленная в одну дверь и не в другую, — это вторая реализация, ровно то, что запрещает данный ADR.
3. **Своя лестница запрещена.** Выбор модели — только общий `trained-assist-llm-ladder` (ladder `conversation`). Никаких собственных конфигов моделей, ключей и fallback-цепочек: это дублирование, которое потом никто не обслуживает.
4. **Рантайм — Cloudflare Worker, не VM.** VM на GCP выводится из эксплуатации (agent#2053, решение владельца 03.10.2026). stdio MCP-сервер не переживёт это: stdio означает локальный дочерний процесс. Поэтому метод живёт в Worker'е и говорит по HTTP, а лестница уже является Worker'ом — путь запроса Worker→Worker, VM в нём нет.
5. **Stateless намеренно.** Нет D1/Vectorize/AI-биндинга. Состояние диалога выводится из переданной истории каждый раз; оригинал истории остаётся источником истины, а не кэш рядом с ним. База понадобится только при измеренной потребности в кэше — вводить её заранее значит платить за миграции, авторизацию и второго владельца durable-state без причины.

## Последствия

- Плюс: одна точка правды по guard'у/бюджету попыток — общий retry budget не перемножается между адаптером, MCP и лестницей.
- Плюс: песочница и CI проверяют ровно тот путь, который уйдёт в прод (stdio JSON-RPC и HTTP-контракт лестницы).
- Плюс: метод не зависит от VM и переживает её вывод из эксплуатации.
- Минус: изменение контракта требует синхронного обновления схем, фикстур и потребителей.
- Минус: Worker-рантайм не даёт произвольных файлов и долгих процессов — длинная история обрабатывается за один вызов, а не фоновой задачей.
- Риск: логика, добавленная только в одну дверь, ломает инвариант — CI и песочница падают, это и есть защита.
