# trained-assist-communication-skills

Общий генератор следующего сообщения в диалоге. Первый потребитель — рекрутинг; далее sales и другие домены.

**Рантайм: Cloudflare Worker** (VM на GCP выводится из эксплуатации — agent#2053, решение владельца 03.10.2026). Метод не зависит от VM: ни файлов, ни процессов, ни локальных секретов. Модель — через общий `trained-assist-llm-ladder`, который сам является Worker'ом, поэтому путь запроса Worker→Worker.

Контракт: [docs/spec.md](docs/spec.md) · ТЗ-альтернатива: [issue #6](https://github.com/trained-assist/trained-assist-communication-skills/issues/6) · эпик — [#1](https://github.com/trained-assist/trained-assist-communication-skills/issues/1)

## Инструмент MCP (contract v1)

`generate_next_message_to_conversation_partner` — пишет ОДНО следующее сообщение по явно заданной цели. Не выбирает шаг процесса, не отправляет. Возвращает черновик.

Что делает сверх простого «напиши сообщение»:

- **Состояние диалога** (`src/dialog-state.mjs`) — извлекается из ПОЛНОЙ истории детерминированно, без вызова модели: отвеченные вопросы, отказы, незакрытые вопросы собеседника, обещания, условия. Каждый факт — дословная цитата с id сообщения, поэтому отрицание не теряется («офис не рассматриваю» не превращается в «рассматриваю офис»).
- **Запрет контакта** → `no_message_needed`, модель НЕ вызывается. Это решение, а не подсказка в промпте.
- **Guard** — детерминированный, не тратит модель: ограничения, повтор, переспрос решённого вопроса, выдуманное время. При отклонении — повтор с объяснением, ЧТО не так (иначе модель повторяет ту же ошибку и бюджет сгорает впустую). Общий retry budget = 2 попытки всего.

## Эндпоинты

| Путь | Что |
|---|---|
| `GET /health` | публичный, без токена; честно сообщает `not_configured`, если нет ladder-конфига |
| `POST /mcp` | MCP streamable HTTP (`initialize` / `tools/list` / `tools/call`) |
| `POST /v1/dialogs/next-message` | тот же handler по REST (issue #6 §1) |

Все, кроме `/health`, требуют `Authorization: Bearer <COMMUNICATION_TOKEN>`.

## Запуск и проверка

```bash
npm ci
npm run gate          # check + 68 тестов + песочница 15/15
npm run dev           # wrangler dev на :8787
```

Песочница — замкнутый цикл без сети и модели: фейковая лестница по реальному HTTP-контракту, настоящий MCP `tools/call`. Она проверяет не только ответ, но и **что реально дошло до модели** (`prompt_contains`) — иначе состояние диалога можно было бы выкинуть и остаться зелёными.

## Границы

- Нет HH tokens и HH API; выбор шага, ATS, хранение черновика, preview и отправка — у потребителя.
- Своя лестница моделей запрещена (ADR-0001): только общий `llm-ladder`, ladder `conversation`.
- Нет D1/Vectorize/AI-биндинга: метод stateless, состояние диалога выводится из переданной истории каждый раз. База понадобится только когда появится измеренная потребность в кэше — см. «Чего здесь нет и почему».

## Чего здесь нет и почему

Из ТЗ issue #6 реализовано то, что чинит реальные дефекты. Остальное отложено по замерам, а не по нежеланию:

| Из ТЗ #6 | Статус | Почему |
|---|---|---|
| §4 Обязательное состояние диалога | **сделано** | чинит реальные дефекты: переспрос отвеченного, игнор запрета контакта, выдуманное время |
| §6 Валидация результата | **сделано** | guard детерминированный, 0 токенов |
| §5 Embeddings (BGE-M3) + Vectorize | отложено | история в рекрутинге ≤ 8 сообщений ≈ 1800 токенов; векторный поиск по такому объёму дороже и менее надёжен, чем передать историю целиком |
| §5 Теги + RRF + budget packing | отложено | то же: нет измеренной потребности в сжатии |
| §8 30 размеченных сценариев | частично | 17 регрессионных кейсов из §8 покрыты тестами; полный корпус — отдельная задача |

Замеры (живой `llm-ladder`, 720 ч): лестница `conversations` — 1126 вызовов, 3.37M входных токенов, $1.05. Это 6.6% всех входных токенов организации, а не главный потребитель (лестница `free` — 41.5M). То есть оптимизация токенов здесь не окупает переписывание — окупает качество: переспрос отвеченного вопроса и письмо человеку, попросившему не писать, стоят дороже токенов.

## Известные ограничения (честно)

- **Перефраз не ловится всегда.** Guard сравнивает слова дословно, без лемматизации: «логистику» и «логистикой» — разные токены. Дословный повтор ловится, близкий перефраз — нет. Тест `известное ограничение: близкий перефраз ловится не всегда` фиксирует это как факт, а не прячет.
- **Состояние диалога — эвристика, не судья.** «Отвечен ли вопрос» определяется структурой (есть ли реплика после), а не смыслом. Неопределённое помечается `replied` с просьбой проверить историю, а не угадывается.
- **Сжатия нет.** Вход > 120000 символов → `INPUT_TOO_LARGE` с размерами, без молчаливого slice. Сжатие относительно цели (contract v1.1) — отдельная задача после baseline.
